# update_changelog_from_commits - 按提交日志归档 CHANGELOG 与 UpdateSummary

## 输入（提交日志内容）

- 用户在消息中直接粘贴提交日志块，每条包含：`版本`（完整 commit 哈希）、`作者`、`日期`、`信息`（标题 + 可选正文要点）。
- 支持一次传入多条提交、跨多个版本日的提交。
- 若用户未粘贴日志，提示粘贴提交日志内容（可配合 git-svn-commitlog-generator 采集），不得自行猜测提交内容。

## 目标文件与角色分工

| 文件 | 受众 | 风格 |
|------|------|------|
| `CHANGELOG.md` | 开发者 | 按功能域分组的小节 + 中文要点子条目，可含实现细节，结尾附「提交参考」完整哈希 |
| `UpdateSummary.txt` | 最终用户 | 每版本一行 `- {版本}：功能点1；功能点2；`，**只暴露功能点，不写实现细节**（如内部模块名、协议、算法、重构手法） |

## 执行流程（严格按序）

1. **确定版本号**：读取 `Properties/AssemblyInfo.cs` 中的 `[assembly: AssemblyVersion("...")]`，取其作为本次归档版本号（四段式，如 4.3.1.0）。用户消息中明确指定版本号时以用户为准。
2. **解析提交日志**：逐条提取完整哈希、日期、类型（feat/fix/perf/refactor/chore 等）、标题与正文要点。
3. **去重**：在 `CHANGELOG.md` 全文搜索每个完整哈希，已出现于「提交参考」的提交跳过，不重复归档。
4. **筛选收录**：仅收录 feat/fix/perf 等有用户可感知改动的提交；纯 chore、临时提交、纯文档微调不单独成条。提交信息中的「同步 MftScanner 工具产物」等工具同步语句不写入用户要点。
5. **更新 CHANGELOG.md**：
   - 该版本章节不存在时，在文件头部说明段之后新建 `## {版本} — {yyyy-MM-dd}`（日期取本次收录提交的最新日期）；已存在时合并进既有章节，不重复建节。
   - 按功能域分组（如「工作日报迭代选择」「AI 提交技能分发」），每组一个三级小节标题 + 若干子条目；单一改动可不分组直接列条目。
   - 受限未开放功能在小节标题后标注「（受限功能）」。
   - 章节末尾追加「提交参考」：`- {完整哈希} — {原始提交标题}`，按提交时间新到旧排列。
6. **更新 UpdateSummary.txt**：
   - 该版本行不存在时在版本列表顶部插入 `- {版本}：功能点；` 一行；已存在时按同样风格改写该行。
   - 每个功能点一个短语，分号分隔，行尾以分号结束；只保留用户可感知的功能与修复，剥离实现细节。
   - 不改动其他版本行。
7. **自查**：版本号一致、无重复哈希、两文件均更新、UpdateSummary 无实现细节泄漏、CHANGELOG 日期与提交日期一致。

## 风格示例

CHANGELOG.md：

```markdown
## 4.3.1.0 — 2026-08-20

- 工作日报迭代选择（受限功能）：
  - 日报页新增迭代下拉框，展示项目未完成迭代与起止日期。
  - 默认迭代智能推荐：上次手选优先，其次今天所在区间、结束最近的未来迭代。

- PingCode 修复：
  - 迭代工作项查询删除 iteration_id 兜底参数，避免误拉全库工作项。

- 提交参考：
- 425695383c2036ded422ec0dacdf7e257949c85f — feat(PackageManager): 工作日报支持迭代选择与默认迭代智能推荐
```

UpdateSummary.txt：

```text
- 4.3.1.0：工作日报支持选择迭代并智能推荐默认迭代；修复迭代查询误拉全库工作项的问题；
```

## 约束

- 只允许修改 `CHANGELOG.md` 与 `UpdateSummary.txt` 两个文件。
- 不改写历史版本内容（用户明确要求精简/修订指定版本行时除外）。
- 提交参考必须使用完整 40 位哈希，标题保持提交原文，不翻译不改写。
- 描述一律使用中文；专有名词（Git、SVN、MSBuild、迭代、PingCode 等）保留原文。
